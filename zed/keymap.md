# Zed 快捷键中文说明：个人配置与 Vim 工作流

本文以你当前生效的 Zed 配置为准，完整整理自定义快捷键，并补充官方 Vim 操作及没有直接 Vim 对应操作的常用 Zed 功能。

整理日期：2026-09-08。系统：macOS。读取到的 Zed 应用版本：1.18.1。

依据：本目录的 [keymap.json](./keymap.json)、[settings.json](./settings.json)，以及你提供的《Zed Vim Sneak 跳转搜索功能》咨询记录。`~/.config/zed/` 下的两个配置文件都是指向本目录的符号链接。官方键位按整理当日的文档和仓库 `main` 核对；仓库开发版可能与安装版不同，本文没有逐项进行界面按键实测。

**阅读规则：自定义键位全部保留；补充功能优先写 Vim 操作，不重复堆放相同功能的 Cmd 快捷键。** 旧记录中的建议仅作为背景，未把其中的修改要求当成当前任务，也没有修改任何现有配置。

## 1. 按键读法与生效范围

| 写法 | 实际按法 |
| --- | --- |
| `Ctrl` / `Cmd` / `Alt` | 分别是 Control（⌃）、Command（⌘）、Option（⌥）；三者不是同一个键 |
| `Ctrl+Alt+,` | 同时按住 Ctrl、Option 和逗号键 |
| `g z` | 先按 `g`，松开，再按 `z`；不是同时按 |
| `Ctrl+w → h` | 先按 Ctrl+w，松开，再按 h |
| `H`、`L`、`S`、`X` | 大写字母，即 Shift 加对应字母 |
| `Shift → Shift` | 连续按两次 Shift，每次都松开 |
| `:w` | 普通模式按 `:`，输入 `w`，再按 Enter；下文所有冒号命令都需要 Enter |
| `Esc` | Escape 键；用于退出当前模式或取消当前交互 |

下面用 **N** 表示普通模式、**I** 表示插入模式、**V** 表示可视模式、**O** 表示算子等待模式。按 `d` 或 `c` 后，等待移动命令或文本对象的阶段就是 O。

| 配置中的 context | 含义与注意事项 |
| --- | --- |
| `Workspace` | 工作区级绑定，通常可在编辑器及面板中使用；更内层上下文仍可能截获按键 |
| `Editor && !menu` | 焦点位于编辑器，且没有相关菜单；没有限定 Vim 模式，所以插入模式也受影响 |
| `VimControl && !menu` | 当前官方定义涵盖 N、V、O；并非注释所写的只有普通与可视模式 |
| `vim_mode == normal / insert / visual` | 只在指定 Vim 模式下匹配 |
| `vim_operator == a / i / cs` | 正在选择 around、inner 文本对象，或 change-surround 的旧包裹对象 |
| `Dock` | 文件树、终端面板等停靠区域；不等于中央编辑器窗格 |

用户绑定可以覆盖默认绑定；焦点所在位置、Vim 模式、菜单和多键前缀都会影响结果。按键之间的空格表示顺序输入，细节见 [官方快捷键说明](https://zed.dev/docs/key-bindings)。

## 3. 自定义快捷键：文件、编辑与模式

### 3.1 文件与基础编辑

以下内容按真实 action 解释，不依赖行尾注释。

| 快捷键 | 范围 | 当前作用 | 使用细节 |
| --- | --- | --- | --- |
| `Ctrl+s` | 工作区；编辑器中也单独绑定 | 保存当前文件 | 对应 `workspace::Save`；Vim 中也可用 `:w` |
| `Shift → Shift` | 工作区 | 打开或关闭文件查找器 | 对应 `file_finder::Toggle`；按文件名查找项目文件，不搜索文件正文；实际识别受按键时序影响 |
| `j k` | I | 退出插入模式 | 对应 `vim::NormalBefore`，语义与插入模式 Esc 一致；不能保证“光标绝对不动”，通常会回到前一个可编辑字符 |
| `Ctrl+c` | 编辑器，无菜单 | 复制 | 对应编辑器复制，使用系统剪贴板；不再作为通常的 Vim 退出键 |
| `Ctrl+x` | 编辑器，无菜单 | 剪切 | 剪切当前选区；不能再把这个单键当作 Vim 数字减一 |
| `Ctrl+v` | 编辑器，无菜单 | 粘贴系统剪贴板 | 不再进入 Vim 块可视模式 |
| `Ctrl+y` | 编辑器，无菜单 | 撤销 | 与常见 Windows 软件习惯不同；不是重做 |
| `Ctrl+f` | 编辑器，无菜单 | 打开当前文件搜索栏 | 替代了 Vim 的向下翻整页；Vim 搜索优先用 `/` |
| `Ctrl+o` | 编辑器，无菜单 | 打开文件或目录对话框 | 不是跳转历史后退，也不是项目文件名模糊搜索 |
| `Ctrl+a` | 编辑器，无菜单 | 全选当前文档 | 替代普通模式的数字加一 |
| `Ctrl+b` | 编辑器，无菜单 | 显示或隐藏左侧 Dock | 不再是 Vim 向上翻整页；左侧可能显示文件树、Git、大纲等面板 |

你的 `base_keymap` 是 `VSCode`，但 macOS 的 VSCode 方案并不意味着自动将复制键变成 Ctrl+c。这里的 Ctrl+c/x/v 等行为来自你显式写入的覆盖。

### 3.2 光标移动、悬浮信息与历史

| 快捷键 | 范围 | 当前作用 | 说明 |
| --- | --- | --- | --- |
| `h` / `←` | N / V / O，无菜单 | 左移，允许跨行 | 到行首后继续左移，可以进入上一行末尾 |
| `l` / `→` | N / V / O，无菜单 | 右移，允许跨行 | 到行尾后继续右移，可以进入下一行开头 |
| `H` | N / V，无菜单 | 到本行第一个非空白字符 | 实际发送 `^`；V 模式下扩展或调整选区；不再表示屏幕顶部 |
| `L` | N / V，无菜单 | 到本行行尾 | 实际发送 `$`；V 模式下调整选区；不再表示屏幕底部 |
| `Cmd+k → Cmd+i` | N / V，无菜单 | 显示 Hover 信息 | 显示类型、文档或诊断等，取决于当前位置与语言服务 |
| `g e` | N / V，无菜单，排除 O | 到上一个子词结尾 | 驼峰名、下划线名可分段移动；`w/b/e` 仍按默认词规则移动 |
| `' .` | N / V / O，无菜单 | 跳转历史后退 | 对应 `pane::GoBack`；不是逐个撤销光标移动，更不是撤销文本编辑 |
| `' ' .` | N / V / O，无菜单 | 跳转历史前进 | 对应 `pane::GoForward`；先后按两次单引号和一次句点 |

`g e` 的自定义规则排除了 O，因此不能推断 `d g e` 也使用子词边界。`H/L` 同样没有覆盖 O；作为独立移动键和作为算子后的移动命令，生效规则可能不同。

历史按键的准确读法：

```text
后退：' → .
前进：' → ' → .
```

这些前缀可能影响原有的 Vim 标记跳转体验；本文仅记录当前结果，没有调整键位。

## 4. 自定义标签跳转与旧 Sneak 方案

### 4.1 当前已启用：`g z`

在 N 或 V 模式下，按 `g z` 调用 `vim::HelixJumpToWord`，为可见单词起点显示跳转标签，然后输入目标处显示的标签。V 模式下使用时应留意选区端点的变化。

```text
Esc → g → z → 输入目标单词旁显示的标签
```

**标签是跳转地址，不是搜索关键词。** 假设你想跳到 `return`，应读它旁边的标签并输入，而不是认为输入 `r` 就会筛选所有 r 开头的词。以界面实际显示的标签长度为准，不必把标签写死成固定字母。

你还配置了 `helix.jump_label_accent: "#ff9e64"`，用于跳转标签的强调色。这不意味着你启用了 Helix 编辑模式；当前开启的仍是 Vim 模式。

该动作属于 Zed 提供、在 Vim 模式中需要自行绑定的功能。参见 [官方 Vim 模式说明](https://zed.dev/docs/vim) 与 [Helix 模式说明](https://zed.dev/docs/helix)。

### 4.2 旧记录提到的 Sneak：当前未启用

| 旧方案 | 作用 | 当前状态 |
| --- | --- | --- |
| `s` → `vim::PushSneak` | 输入两个字符，向文档后方寻找字符组合，可跨行 | 映射已注释 |
| `S` → `vim::PushSneakBackward` | 输入两个字符，向文档前方寻找字符组合 | 映射已注释 |
| `;` / `,` | 重复字符查找 / 反向重复；也可用于已配置的 Sneak | 当前仍可用于正常的 `f/t/F/T` 查找，不代表 Sneak 已启用 |

当前普通模式 `s` 仍是替换字符并进入插入，`S` 仍是整行替换；可视模式的 `S` 被你改成添加包裹。旧记录中关于“`g s` 被 Sneak 占用”的判断不适用于现在的文件。

## 5. 文本对象、包裹与交换

### 5.1 先理解“操作 + 范围”

文本对象告诉 Vim **对哪一段文本执行操作**。`i` 表示内部，`a` 表示包含外围；这两个字母在算子后或可视模式中的含义，与普通模式下进入插入模式不同。

```text
c i q
│ │ └─ 任意引号对象（你的自定义 q）
│ └─── 只取内部，不包括引号
└───── 修改：删除对象内容并进入插入模式
```

同一范围可以搭配 `d` 删除、`c` 修改、`y` 复制、`v` 选择。

### 5.2 你配置的四种对象

| 对象键 | Action | 匹配对象 | 选择特点 |
| --- | --- | --- | --- |
| `q` | `vim::AnyQuotes` | 单引号、双引号、反引号 | 传统 Any 对象策略，优先寻找适合当前位置的最近包裹 |
| `b` | `vim::AnyBrackets` | 小括号、方括号、大括号、尖括号 | 按括号字符匹配；尖括号与代码运算符可能存在歧义 |
| `Q` | `vim::MiniQuotes` | 同一组引号 | mini.ai 风格策略，优先考虑当前行后再向外寻找 |
| `B` | `vim::MiniBrackets` | 同一组括号 | mini.ai 风格，更重视语法上下文；不等于永远只选大括号 |

这里的“Mini”是不同的对象选择策略，不是“选区更小”的保证；语言解析、光标位置与周围文本都会影响选择结果。策略区别参考 [官方 Any/Mini 文本对象说明](https://zed.dev/docs/vim#any-bracket-functionality)。

如果明确要操作某一种括号，直接使用实际字符更准确：

| 范围 | 内部 | 连同外围 | 用途 |
| --- | --- | --- | --- |
| 小括号 | `i(` | `a(` | 参数列表、分组表达式 |
| 大括号 | `i{` | `a{` | 代码块、对象字面量 |
| 方括号 | `i[` | `a[` | 数组、索引表达式 |
| 双引号 | `i"` | `a"` | 明确指定双引号字符串 |
| 单词 | `iw` | `aw` | 单词内部，或带相邻空白的词范围 |
| 函数 / 方法 | `if` | `af` | 函数内部，或整个函数定义 |
| 类 / 定义 | `ic` | `ac` | 类内部，或整个类定义 |
| 参数 / 列表项 | `ia` | `aa` | 单个参数；around 会处理相邻分隔部分 |
| HTML / JSX 标签 | `it` | `at` | 标签内部，或连同外层标签 |
| 缩进块 | `ii` | `ai` / `aI` | 当前缩进层级；around 还涉及前一行，`aI` 还涉及后一行 |
| 注释 | `gc` | — | 作为对象使用，例如算子后输入 `gc`；与普通模式 `gcc` 的注释操作要区分 |

函数、类、注释对象依赖语言的 Tree-sitter 查询支持，`if/af` 不应简单理解为“找最近一对大括号”。以上默认对象根据 [官方 Vim 键位源码](https://github.com/zed-industries/zed/blob/main/assets/keymaps/vim.json) 核对。

### 5.3 添加、修改和删除包裹

| 按法 | 模式 | 作用 |
| --- | --- | --- |
| `ys` + 范围 + 包裹字符 | N | 为指定范围添加包裹；Zed 内置 surround 功能 |
| `cs` + 旧包裹 + 新包裹 | N | 替换已有包裹，保留内部文本 |
| `ds` + 包裹字符 | N | 删除包裹，保留内部文本 |
| 选区后 `S` + 包裹字符 | V，**自定义** | `vim::PushAddSurrounds`：为选区添加包裹；覆盖可视模式默认的行替换 |

```text
选中 hello → S → "
结果："hello"
```

### 5.4 交换两段文本

| 按法 | 模式 | 作用 |
| --- | --- | --- |
| 第一段选区按 `X`，再选择第二段按 `X` | V，**自定义** | `vim::Exchange`：先标记第一段，再交换两段；不是剪切 |
| `cx` + 范围，随后对另一范围重复 | N，官方内置 | 通过算子与文本对象选择两段并交换 |

你的 `X` 覆盖可视模式的默认按行删除操作。只想删除当前选区时使用 `d`。

## 6. 窗格、Dock 与终端

### 6.1 三种区域要分清

| 区域 | 典型内容 | 应使用的尺寸控制 |
| --- | --- | --- |
| 中央编辑区窗格 Pane | 左右或上下排列的源代码编辑器 | 你的 Ctrl+Alt 尺寸键，或 Vim `Ctrl+w` 系列 |
| 停靠区 Dock | 左侧文件树、右侧 Agent、底部终端面板 | 官方 Dock 尺寸键 |
| 终端面板内部的分屏 | 同一终端面板中并排运行的 shell | 不等于中央窗格；不能直接保证编辑区 resize 动作适用 |

### 6.2 你的编辑区尺寸快捷键

以下自定义绑定全部位于 `Editor && !menu`，因此聚焦代码编辑器时，N/I/V 等模式均可匹配；聚焦终端本体时不属于这个范围。

| 快捷键 | Action | 作用 | Vim 对应操作 |
| --- | --- | --- | --- |
| `Ctrl+Alt+,` | `vim::ResizePaneLeft` | 缩小当前窗格宽度 | `Ctrl+w → <` |
| `Ctrl+Alt+.` | `vim::ResizePaneRight` | 增大当前窗格宽度 | `Ctrl+w → >` |
| `Ctrl+Alt+[` | `vim::ResizePaneDown` | 减小当前窗格高度 | `Ctrl+w → -` |
| `Ctrl+Alt+]` | `vim::ResizePaneUp` | 增大当前窗格高度 | `Ctrl+w → +` |
| `Ctrl+Alt+\` | `vim::ResetPaneSizes` | 重置中央分屏比例，使窗格重新等分 | `Ctrl+w → =` |
| `Ctrl+Alt+=` | `vim::ResetPaneSizes` | 同样重置中央分屏比例；这是仍保留的重复入口 | `Ctrl+w → =` |
| `Ctrl+Alt+m` | `workspace::ToggleZoom` | 放大当前窗格，再按一次还原 | 无完全相同的传统 Vim 操作 |

宽高调整需要该方向存在可分配的空间，且受窗格最小尺寸和布局限制。左右两个窗格本来一样高时，调整高度通常没有可见变化；上下窗格的宽度同理。重复按键可连续调整，长按效果取决于系统按键重复设置。

```text
让左侧编辑器给右侧腾空间：
聚焦左侧代码 → 连按 Ctrl+Alt+, → 满意后停止
需要重新等分：Ctrl+Alt+\
```

**放大不等于等分。** `Ctrl+Alt+m` 是显示上的 zoom 切换，优先再次按同一个键还原；`Ctrl+Alt+\` 调整的是分屏比例，并不负责替你撤销 zoom。

旧记录的 `Ctrl+w → _` → `vim::MaximizePane` 调整的是高度，不能当成完整的窗格 zoom。官方仓库讨论记录了左右分屏中可能看不到效果的原因；当前默认键表仍把 `_` 绑定到该动作。参见 [横向最大化讨论](https://github.com/zed-industries/zed/discussions/38964)。

`Shift+Esc` 是官方的 `workspace::ToggleZoom` 入口；与你自定义的 `Ctrl+Alt+m` 是同一个动作，但可用于更广的界面范围。此处保留它，是因为它也是旧记录的重要内容，并且传统 Vim 高度最大化不能替代它。

### 6.3 切换焦点、分屏和标签

| 按法 | 作用 | 说明 |
| --- | --- | --- |
| `Ctrl+w → h/j/k/l` | 焦点移到左 / 下 / 上 / 右 | 编辑区为 Vim 内置；你额外在 Dock 上绑定了这四个方向 |
| `Ctrl+w → w` | 切换到下一个窗格 | 在多个编辑窗格之间循环 |
| `Ctrl+w → v` | 左右分屏 | 也可输入 `:vsplit` |
| `Ctrl+w → s` | 上下分屏 | 也可输入 `:split` |
| `Ctrl+w → c` | 关闭当前活动标签 | 动作为 `pane::CloseActiveItem`，不是无条件关闭包含多个标签的整个窗格 |
| `Ctrl+w → H/J/K/L` | 向左 / 下 / 上 / 右移动窗格 | 大写代表改变布局，不是仅移动焦点 |
| `g t` / `g T` | 下一个 / 上一个标签 | 标签属于当前窗格，与跳转历史不同 |
| `Ctrl+w → g d` | 在分屏中打开定义 | 适合保留调用处同时阅读实现 |

`Ctrl+w` 窗格命令优先在普通模式使用。在插入模式中单独 `Ctrl+w` 是向前删词；终端中可能被 shell 或前台程序消费。Dock 映射不能据此保证所有嵌套终端程序都能用同一套按键切焦点。

以上默认窗格动作见 [官方 Vim 键位源码](https://github.com/zed-industries/zed/blob/main/assets/keymaps/vim.json)。

### 6.4 官方 Dock 尺寸键

先将焦点放到目标 Dock，再用“当前 Dock”一组。对于左右 Dock，尺寸主要表现为宽度；对于底部 Dock，主要表现为高度。

| 按法 | 作用 | Action |
| --- | --- | --- |
| `Ctrl+Alt+-` | 缩小当前活动 Dock | `workspace::DecreaseActiveDockSize` |
| `Ctrl+Alt+=` | 增大当前活动 Dock | `workspace::IncreaseActiveDockSize` |
| `Ctrl+Alt+0` | 重置当前 Dock 尺寸 | `workspace::ResetActiveDockSize` |
| `Ctrl+Alt+_` | 缩小所有打开的 Dock | `workspace::DecreaseOpenDocksSize` |
| `Ctrl+Alt++` | 增大所有打开的 Dock | `workspace::IncreaseOpenDocksSize` |
| `Ctrl+Alt+)` | 重置所有打开的 Dock 尺寸 | `workspace::ResetOpenDocksSize` |

美式键盘中，后三个符号通常分别需要 Shift+-、Shift+=、Shift+0；这里的 `+` 符号是实际要输入的键，不只是组合键分隔符。

**你当前的冲突是上下文相关的：** 聚焦编辑器且无菜单时，`Ctrl+Alt+=` 会走你的 `vim::ResetPaneSizes`；聚焦文件树或终端等 Dock 时，才可能走默认的增大 Dock。Agent 输入框等嵌套编辑器也可能匹配 `Editor`，不能笼统承诺“只要在 Dock 里就不会冲突”。文件树可先点选一个条目，再调宽度。

这些键改变整个终端 Dock 的高度或宽度，不是它里面两个终端之间的比例。旧记录声称内部终端分屏“只能鼠标拖”，本文不将其当作已验证的现状；可以直接拖动分隔线，或通过命令 `workspace: new center terminal` 把终端放在中央标签区。即便放到中央，终端焦点仍不匹配你写的 `Editor` 尺寸绑定。

来源：[官方 macOS 默认键位源码](https://github.com/zed-industries/zed/blob/main/assets/keymaps/default-macos.json)、[官方终端说明](https://zed.dev/docs/terminal)。

### 6.5 你的终端入口

`Ctrl+Shift+j` → `terminal_panel::ToggleFocus`：切换终端面板焦点，面板隐藏时可将其带出。该条没有显式 context，不局限于 Vim 普通模式。

当前终端 shell 配置为 `/opt/homebrew/bin/fish`。进入终端后，普通字母是发给 shell 的输入，不能直接用编辑器的 `h/j/k/l` 当作移动键。

## 7. 官方 Vim 补充：搜索与代码结构跳转

本节以当前 [官方 Vim 键位源码](https://github.com/zed-industries/zed/blob/main/assets/keymaps/vim.json) 为依据；除特别注明，按普通模式使用。

### 7.1 搜索与定位

| 按法 | 作用 | 适合的场景 |
| --- | --- | --- |
| `/关键词` | 向后搜索，Enter 确认 | 知道目标文本，但不知道具体位置 |
| `?关键词` | 向前搜索，Enter 确认 | 查找当前光标之前的内容 |
| `n` / `N` | 沿当前搜索方向继续 / 反方向继续 | `n` 不恒等于向下；如果用 `?` 开始，方向也相应改变 |
| `*` / `#` | 向后 / 向前搜索光标下的词 | 找相同名字的其他出现位置；不是语义引用查找 |
| `f` / `F` + 字符 | 本行向右 / 向左找到该字符 | 光标停在目标字符上 |
| `t` / `T` + 字符 | 本行向右 / 向左查找，但停在目标之前 / 之后 | 适合与删除、修改算子组合 |
| `;` / `,` | 重复最近字符查找 / 反向重复 | 属于 `f/t/F/T` 系列，不代替 `/` 搜索的 `n/N` |
| `g /` | 打开项目全文搜索 | 搜索多个文件中的文本 |
| `g Space` | 打开当前搜索结果摘录对应的文件位置 | 在多文件搜索结果中返回原文件 |
| `g g` / `G` | 文件开头 / 结尾 | 与行内的 `H/L` 不同 |
| 行号 + `G` | 跳到指定行 | 输入绝对行号；相对行号模式不会改变它的含义 |
| `Ctrl+d` / `Ctrl+u` | 下滚 / 上滚半屏 | 你的 Ctrl+f/b 已被覆盖，半屏操作仍保留 |
| `z z` / `z t` / `z b` | 当前光标行放到视口中间 / 顶部 / 底部 | 调整视野，不是修改文本 |

你设置了 `use_smartcase_find: true`，用于字符查找类行为的智能大小写。不要仅凭这个设置推断 `/` 与项目搜索栏的大小写状态；后者还受搜索选项控制。

### 7.2 括号与代码块

| 按法 | 作用 | 注意 |
| --- | --- | --- |
| `%` | 在匹配的括号等分隔符之间跳转 | 把光标放在目标括号上最直观；Zed 默认动作还启用了引号匹配 |
| `[ {` | 向前找未匹配的左大括号 | 常用于回到当前包围块的开头 |
| `] }` | 向后找未匹配的右大括号 | 常用于离开当前包围块，到其结束位置 |
| `[ (` | 向前找未匹配的左小括号 | 回到包围当前表达式的括号开头 |
| `] )` | 向后找未匹配的右小括号 | 到当前括号表达式的末尾 |
| `{` / `}` | 上一个 / 下一个段落边界 | 主要按空行分段，不等于按 JavaScript 代码块跳转 |

这里“未匹配”指沿扫描方向计算后的包围边界，并不是说你的代码存在语法错误。

### 7.3 函数、类、注释与缩进

| 按法 | 作用 |
| --- | --- |
| `] m` / `[ m` | 下一个 / 上一个函数或方法的开头 |
| `] M` / `[ M` | 下一个 / 上一个函数或方法的结尾 |
| `] ]` / `[ [` | 下一个 / 上一个 section 的开头，通常与类或定义有关 |
| `] [` / `[ ]` | 下一个 / 上一个 section 的结尾 |
| `] /` / `[ /` | 下一个 / 上一个注释；`] *` / `[ *` 是同类入口 |
| `[ x` / `] x` | 扩展到更大的语法节点 / 缩小语法选区 |
| `[ -` / `] -` | 上方 / 下方缩进更浅的位置 |
| `[ +` / `] +` | 上方 / 下方缩进更深的位置 |
| `[ =` / `] =` | 上方 / 下方相同缩进层级的位置 |

函数和 section 的边界与对应的 `af/ac` 对象有关，受语言查询支持影响；没有类时，section 可使用函数作为目标。对于 TSX/JSX，不能仅凭“出现一个箭头函数”就保证每种扩展版本都将它识别为同一种可跳转函数对象。

## 9. 剪贴板、保存与命令别名

### 9.1 系统剪贴板与 Vim 寄存器分开使用

你设置了 `vim.use_system_clipboard: "never"`，因此日常 Vim 复制、删除默认不自动联动系统剪贴板。

| 使用方式 | 操作的数据 |
| --- | --- |
| `y`、`d`、`p` 等 Vim 操作 | Vim 寄存器；日常删除不会自动替换系统复制内容 |
| 你的 `Ctrl+c/x/v` | 编辑器系统剪贴板操作 |
| `"+` 前缀 + Vim 操作 | 显式指定系统剪贴板寄存器 |

```text
"+yy
把当前整行复制到系统剪贴板，可到浏览器或其他应用粘贴。
```

所以“Ctrl+c 复制后用 p 粘贴”和“yy 后用 Ctrl+v 粘贴”不应被当成固定配对；要明确自己使用的是哪一套数据。

### 9.2 保存、关闭与窗口命令

| 命令 | 作用 |
| --- | --- |
| `:w` | 保存当前文件 |
| `:wa` | 保存所有打开的文件 |
| `:wq` | 保存并关闭当前活动文件 |
| `:q` | 关闭当前活动文件；存在未保存修改时按界面提示处理 |
| `:q!` | 强制关闭并放弃尚未保存的修改；已经自动保存到磁盘的内容不会被撤回 |
| `:qa` | 关闭所有缓冲区 |
| `:ls` | 显示打开的缓冲区 |
| `:tabnew` | 新建文件标签 |
| `:Explore` | 打开项目面板 |
| `:term` | 打开终端 |
| `:AI` | 打开 AI 面板 |
| `:clist` | 打开诊断列表 |
| `:Extensions` | 打开扩展管理 |
| `:set wrap` / `:set nowrap` | 开启 / 关闭当前缓冲区软换行 |

这些是 Zed 支持的 Vim 风格命令，不代表完整实现 Vim 命令行。命令支持范围见 [官方 Vim 命令说明](https://zed.dev/docs/vim#command-palette)。

你的 `command_aliases` 另外启用了 `:W` → `:w`、`:Wq` → `:wq`、`:Q` → `:q`，用于容忍 Shift 没及时松开产生的大写；**不是任意大小写组合都自动等价**。

保存还受以下现有设置影响：

- `autosave: "on_focus_change"`：焦点离开文件时会触发自动保存，不必每次手动 Ctrl+s。
- `format_on_save: "on"`、`formatter: "language_server"`：保存时请求语言服务格式化；格式化能力取决于该语言服务。
- `source.fixAll.eslint: true`：格式化流程还请求 ESLint 可修复项；没有对应服务或规则时，不保证会产生修改。
- `toggle_relative_line_numbers: true`：普通模式显示相对行号，插入模式切换行号显示；不改变跳转命令的绝对行号含义。

### 9.3 当前文件替换

当需要按文本批量替换而非语义重命名，可使用 Vim 风格替换命令：

```vim
:%s/oldName/newName/g
```

`%` 表示整个当前文件，`g` 表示每行替换全部匹配；这不是项目全局替换。Zed 的搜索与替换正则语法不完全等于原生 Vim，复杂 Vim 正则不要直接照搬。

### 9.4 自定义特殊字符

你在 `custom_digraphs` 中配置了 `fz` → `🧟‍♀️`。插入模式使用内置 digraph 输入：

```text
Ctrl+k → f → z
```

这里的 `fz` 是两个连续字符，不是快捷键修饰符；只在进入 digraph 输入后解释为这个特殊符号。

| 官方序列 | 对应功能 | 当前说明 |
| --- | --- | --- |
| `Ctrl+x → Ctrl+o` | 打开补全菜单 | 存在 Ctrl+x 前缀重叠 |
| `Ctrl+x → Ctrl+c` | 请求编辑预测 | 不应仅理解为 GitHub Copilot，实际取决于配置的预测提供方 |
| `Ctrl+x → Ctrl+a` | 打开行内 AI 助手 | 存在 Ctrl+x 前缀重叠 |
| `Ctrl+x → Ctrl+l` | 打开代码操作菜单 | 普通模式可直接使用 `g .` |
| `Ctrl+x → Ctrl+z` | 取消相关建议 | 存在 Ctrl+x 前缀重叠 |

不依赖这个前缀的补全菜单入口是编辑器的 `Ctrl+Space`，但 macOS 若将其分配给输入法切换，会先被系统截获。VSCode 基础方案还提供 `Cmd+i` 打开行内 AI；它与普通模式 `g .` 的代码操作不是同一种功能。

序列和动作核对自 [官方 Vim 源码](https://github.com/zed-industries/zed/blob/main/assets/keymaps/vim.json)，VSCode 的行内 AI 入口见 [官方 VSCode 基础键位](https://github.com/zed-industries/zed/blob/main/assets/keymaps/macos/vscode.json)。

## 11. 文件树中的 Vim 操作

先用 `:Explore` 打开项目面板。下表仅适用于 **文件树获得焦点且没有正在编辑文件名** 时；它们与代码编辑器中的同名按键含义不同。

| 按法 | 作用 |
| --- | --- |
| `j` / `k` | 选择下一个 / 上一个条目 |
| `h` / `l` | 收起 / 展开所选条目 |
| `g g` / `G` | 选择首个 / 最后一个条目 |
| `-` | 选择父级条目 |
| `Enter` 或 `t` | 正式打开文件，不只作为临时预览 |
| `p` | 打开所选条目，具体预览行为按当前设置 |
| `v` | 在左右分屏中打开 |
| `o` | 在上下分屏中打开；旧记录笼统说“o 打开文件”不够准确 |
| `%` | 新建文件；在代码里 `%` 才是括号匹配 |
| `d` | 新建目录；在文件树中不是 Vim 删除算子 |
| `R` | 重命名文件或目录 |
| `D` | 删除选中的文件或目录；是文件操作，不是删一行文本 |
| `/` | 在所选目录发起搜索 |
| `x` | 在系统文件管理器中显示所选条目 |
| `Esc` | 切换项目面板焦点，返回编辑工作流 |

来源：[官方 Vim 键位中的 ProjectPanel 上下文](https://github.com/zed-industries/zed/blob/main/assets/keymaps/vim.json)。

## 12. 未启用的内容与只读排查方法

### 12.1 当前没有启用的映射

| 内容 | 当前状态 |
| --- | --- |
| `s/S` Sneak | 已注释；不要照旧记录当成正在使用 |
| `w/b/e` 子词移动 | 已注释；只启用了 `ge` |
| `Y` → `y $` | 已注释；当前 `Y` 按默认复制整行处理 |
| `c l c` / `c u c` 大小驼峰转换 | 已注释；不能作为现成的三键转换命令 |
| 空窗格 `Space f` | 你的 `EmptyPane || SharedScreen` 块里没有有效绑定；官方非编辑器上下文可能有自己的入口，不能称为个人已启用配置 |
| 旧建议的 `Alt+b/e/n/p` | 当前文件中不存在这些自定义映射 |

### 12.2 快捷键与预期不同时

1. 先确认焦点在代码编辑器、文件树还是终端，再确认 Vim 模式。
2. 检查当前是否显示补全、搜索或其他菜单；你的许多映射带有 `!menu`。
3. 打开快捷键编辑器，按 action 名称或实际按键查询；同时查看匹配上下文。
4. 对照安装版默认键位，避免把网站 `main` 的新增内容误认为本机已经支持。
5. 必要时打开按键上下文视图，观察实际按键触发了哪个动作。

普通模式按 `:` 后，可以分别搜索下列命令；这些是查看入口，不是修改配置的脚本：

```text
zed: open keymap
zed: open default keymap
dev: open key context view
```

检查多键序列时，务必按顺序松开再按下一键；检查 `Ctrl+Alt+=` 时，分别在代码区和文件树测一次，才能区分自定义等分与默认 Dock 增宽。
